# SceneSignal SS-32 — Producer and public-release runbook

Status: **NOT QUALIFIED FOR PUBLIC LIVE SPEAKER DEPLOYMENT**.
This runbook is a documentation and rehearsal artifact, not evidence of completed
SS-31 scale qualification or permission to operate at a venue. The controlled
SS-30 field pilot and SS-31 staged scale review must succeed with real device,
consent, site and acoustic evidence before the release gate can change.

## Organizer — authority and public information
1. Confirm a current site plan, the relevant permit or organizer attestation,
   audience access requirements, licensing and privately retained source evidence.
2. Obtain current verified performer and contributor consent. Do not assume
   submitting a phone, QR code, payment, or visiting a public page is consent
   to speaker output, recording, or location tracking.
3. Assign a human event lead and safety lead using secure contact records.
   Public guides may disclose only approved venue-area and accessibility copy.
4. Publish a free-attendance alternative for visitors without phones or accounts.
   Verify quiet routes, large-print signage and access procedures physically.
5. Revalidate live safety authorization after any site-plan revision. If the
   plan changes, stop the old coordinator, revoke stale leases and republish.

## Operator — technical preflight and emergency stops
1. Check current authorized session, signed playback/output lease, encrypted
   source entitlement, gain caps and the current site revision.
2. Verify every output owner has consented, device position is calibrated and
   the route does not duplicate a physical output. Phone motion is not a
   speaker-position measurement.
3. Confirm real field evidence for timing, acoustic limits, audio monitoring,
   speaker dropout, weather/access and an independent emergency stop.
4. Use a controlled stop on a verified hazard, stale authorization, unexpected
   output, lost consent or unsafe volume. Never recover by clearing a lease,
   bypassing checks or manually overriding the source registry.
5. Log a minimal private incident classification, observed time, operator
   identity and durable evidence reference; do not put names, permit files,
   keys or location telemetry in public issue trackers.

## Performer — rehearsal and monitoring
1. Confirm intended microphone routing, monitor level, privacy, recording
   consent, set changes and a human contact for immediate stop.
2. Real latency/jitter measurement and independent performer monitoring must
   pass the published, site-specific acceptance policy before any live input.
3. Falling back to prerecorded, separately licensed material is acceptable
   when live input or synchronization cannot be verified. Never simulate a
   field pass or conceal failed pilot results.

## Contributor and public attendee
1. Speaker participation is voluntary and separately consented; attendance
   is free and never requires lending a device.
2. Only a verified, short-lived output lease may route encrypted content.
   A payment, contribution receipt or public access link cannot start output.
3. Provide non-device instructions, accessible formats and a physical human
   stop/contact path. Never claim a quiet route has been checked merely
   because it appears in a proposed map or software test.
4. Neutral verified contribution facts are not payouts, entitlements or
   automatic revenue shares.

## Release evidence ledger — all gates required
- [ ] Exact source commit, mapped PR, successful current-head CI, and
      satisfied actual branch protection and review requirements
- [ ] Completed SS-24–SS-31 source integration and accepted prerequisites
- [ ] Real SS-30 10–20-output pilot evidence with observed failures retained
- [ ] Real SS-31 staged scale acoustic qualification and declared supported limits
- [ ] Site and public access audit, participant/performer consent and verified
      emergency stop procedure
- [ ] Financial/privacy/retention review and independent signed source/rights
      authorization before any payouts, recordings or distributed playback
- [ ] Human owner signs the release record with evidence timestamps and
      immutable references; no automated agent declares this section passed

## Rehearsal versus release
Source unit tests, isolated simulators, draft web previews and test verifier
callbacks exercise code paths only. They never certify hardware, vendor
availability, audience access or a payable transaction. Keep all release
claims disabled until the final signed real-world acceptance record exists.
If any gate fails, preserve the original evidence, stop output when required,
return to an authorized offline rehearsal and resume development on independent
units rather than bypassing the failed gate.
